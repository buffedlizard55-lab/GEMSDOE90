How to make a submission — exact steps

Summary: download one file, open the submission page, choose the file, paste the note, submit. Nothing is renamed, unzipped or converted.
  1. Download the file. ⬇ gems90-cnc-35000dots-20261024T084324Z.tif Keep the name as it is — it is unique and carries the method, dot count and timestamp. Verify it if you like:
    sha256sum gems90-cnc-35000dots-20261024T084324Z.tif → e1e91be23d763ee184839f38a22aa573d6c957aac8fd0038a680cf6615ef41eb
  2. Open the competition submission page and sign in. Check the weekly quota shown there (the rules allow a limited number of scored submissions per week per team).
  3. "File to submit": choose the downloaded .tif. A single-band GeoTIFF is accepted directly; a .zip containing exactly one GeoTIFF is also accepted. Do not upload both.
  4. "Note" (optional, helps you tell submissions apart): paste 
    Fold-honest discovery model; greedy DTI-optimal dots at the holdout-optimal budget. Off-catalogue, not a collar file. No score claimed.
    (135 characters, within the form's short-comment intent of ≤140.)
  5. Submit, then copy the score the page returns back into ledger/submissions.csv as an ORGANIZER-CONFIRMED receipt. Until that is done, every number in this repository stays labelled MODEL or HOLDOUT-DTI.

If the form rejects the file

messagecausefix
Predicted values must be in range [0, 1] The raster contains NaN (or a nodata sentinel such as -3.4e38). NaN is not in [0,1], so a NaN-outside-footprint file is rejected even though it is otherwise valid. Use the file linked above: it is the all-finite encoding (zeros outside the footprint, 0 non-finite pixels in the whole raster).
CRS / shape / transform mismatch The raster must be exactly the submission-format grid. This file is EPSG:32611, 3730×3292 at 100 m, with the sample transform; python -m src.submission_writer's validator re-checks all three from disk.
Multiple bands / wrong dtypeOnly one float32 band is accepted. This file is single-band float32.
