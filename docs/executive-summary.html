2. Root-Cause Resolution of DrivenData Error: "Predicted values must be in range [0, 1]"

Earlier submissions across sibling runs encountered the DrivenData portal rejection "Predicted values must be in range [0, 1]". Direct byte-level inspection of sample_submission.tif, training_features.tif, and historically scored -zeros files (h33-h33-2-b2-...-zeros.tif at 0.2778 and anderson-geothermal-pinn-...-zeros.tif at 0.2750) pinpointed three root causes and established a deterministic guarantee (`IR90-45`):

  • Root Cause A — Unmasked `-3.4028235e+38` Float32 Sentinels Inside the Active Footprint: In training_features.tif (`19` bands), `3,061` pixels inside the active `5,167,373`-pixel competition footprint carry float32 sentinel values -3.4028235e+38 rather than NaN. Any linear combination, spatial convolution, or unclipped tree/neural output that ingests those sentinels emits extreme negative or `>1.0` predictions inside the active evaluation mask.
  • Root Cause B — `NaN` vs `0.0` Outside-Footprint Handling & `nodata` Metadata Mismatches: While sample_submission.tif stores NaN on the `7,111,787` outside-footprint cells (`nodata=NaN`), writing `NaN` without matching tag semantics—or leaking `NaN` into any of the `5,167,373` inside-footprint cells where lidar_scarp_features_u8.tif has `24.6%` missing coverage—triggers range validation failures (`!(x >= 0.0 && x <= 1.0)` evaluates `True` on `NaN`!).
  • Verified Portal-Safe Solution (`-zeros` All-Finite Contract): Both h33-h33-2-b2-20261004T220000Z-e5eb6e7e-zeros (`0.2778`) and anderson-geothermal-pinn-38854-20261004T230000Z-9b9ea4e6-zeros (`0.2750`) proved on the live DrivenData scorer that setting `0.0` outside the footprint with `nodata=None` passes portal validation cleanly with zero score penalty (DrivenData masks outside-footprint cells via its own footprint mask before scoring). Our pipeline filters `|x| < 1e30` on every band, imputes missing LiDAR cells explicitly via a `lidar_valid` indicator, writes strictly binary `{0.0, 1.0}` `float32` values (`nodata=None`), and re-opens the written GeoTIFF from disk to verify `0` NaN, `0` Inf, `min == 0.0`, and `max == 1.0` across all `12,279,160` pixels.
